# GameChain — система учёта и передачи игровых предметов на основе технологии блокчейн

Демонстрационная программа: показывает, как с помощью хеширования **SHA-256** и **блокчейна**
можно обнаруживать несанкционированные изменения данных учётных записей пользователей.

**Сайт:** https://gordeygs.github.io/gamechain/

## Запуск

Нужен только Python 3.8+ (сторонние библиотеки не используются).

```bash
python3 gamechain.py --demo
```
— автоматическая демонстрация всех сценариев.

```bash
python3 gamechain.py
```
— интерактивное меню. Данные сохраняются в `gamechain_data.json`.

### Сайт (визуальная версия)

Откройте `index.html` двойным кликом — он работает в браузере без сервера и интернета.

- карточки игроков (база данных) с SHA-256 отпечатком каждой записи и инвентарём из ячеек;
- каталог из 20 предметов с пиксельными иконками и редкостью (обычный → легендарный);
  предмет для выдачи или передачи выбирается кликом по иконке. В блокчейн записывается название
  предмета, поэтому каталог совпадает с Python-версией (там выбор по номеру);
- лента блоков: хеш, `prev_hash`, nonce, стрелки-связи между блоками;
- кнопка **«Взломать»** на карточке — правка базы в обход блокчейна;
- клик по **блоку** — подделка старой записи (с пересчётом хеша или без);
- **«Проверить»** — анимированный проход по цепочке, нарушения подсвечиваются красным;
- **«Откатить взлом»** — вернуть состояние до атаки, а если снимка нет (например, импортирован уже
  взломанный файл) — восстановить базу по блокчейну. Пока есть нарушения, операции заблокированы;
- **журнал событий безопасности** — хронология атак (что именно изменено), проверок с их результатами
  и откатов. Это журнал администратора: он хранится отдельно и в блокчейн не входит;
- **Экспорт / Импорт JSON** — формат совпадает с `gamechain_data.json` Python-версии.

## Как это устроено

| Компонент | Назначение |
|---|---|
| `Block` | Блок: номер, время, тип операции, данные, `prev_hash`, `nonce`, `hash` |
| `Blockchain` | Цепочка блоков, добыча (Proof-of-Work), проверка целостности |
| `GameChain` | Учётные записи игроков («база данных») + запись каждой операции в блокчейн |

**Операции, которые попадают в блокчейн:** регистрация пользователя, изменение данных профиля
(никнейм, email, уровень, золото), выдача предмета, передача предмета между игроками.

**Как используется SHA-256:**
1. **Хеш блока** — SHA-256 от всего содержимого блока. Любое изменение данных меняет хеш.
2. **Связь блоков** — каждый блок хранит хеш предыдущего (`prev_hash`), поэтому изменение
   одного блока ломает всю цепочку после него.
3. **Proof-of-Work** — хеш блока должен начинаться с `0000`; чтобы подделать историю,
   пришлось бы заново «добывать» все последующие блоки.
4. **Отпечаток учётной записи** — при каждом изменении в блок записывается SHA-256 новой
   версии записи пользователя. Если запись в базе изменили в обход системы, хеш не совпадёт.
5. **Пароли** хранятся только как SHA-256 хеш с солью.

## Какие атаки обнаруживаются

| Атака | Как обнаруживается |
|---|---|
| Подмена данных учётной записи в базе (золото, email, предметы) | SHA-256 записи ≠ хешу записи, восстановленной по блокчейну; показывается, какое поле изменено |
| Изменение старой записи в истории | Пересчитанный хеш блока ≠ записанному |
| Изменение блока с пересчётом его хеша | Нарушен Proof-of-Work и `prev_hash` следующего блока |
| Удаление / добавление учётной записи в обход блокчейна | Запись отсутствует в истории блоков |
| «Отмывание» взлома: новая операция поверх подменённых данных | Операции блокируются, пока есть нарушения. Если такой блок всё же попал в цепочку, отпечаток в нём ≠ состоянию, восстановленному по истории |
| Дюп предмета: передача предмета, которого у игрока не было | При восстановлении по истории блок — «невозможная операция» |

**Как проверяется каждый блок.** Состояние учётных записей восстанавливается с нуля, блок за блоком.
После каждого блока записанный в нём SHA-256 отпечаток сверяется с хешем записи, которая должна
получиться по истории, а сама операция проверяется на возможность. Затем база данных сравнивается
с восстановленным состоянием.

**Блокировка и восстановление.** Пока проверка находит нарушения, новые операции отклоняются (иначе
новый блок закрепил бы подменённые данные). Восстановление: на сайте — кнопка «Откатить взлом»,
в Python-версии — пункт меню 11. Цепочка обрезается до последнего корректного блока, а база
собирается заново из истории блоков.

## Как показать на защите

1. Запустить `python3 gamechain.py`, зарегистрировать 2 игроков, выдать и передать предметы.
2. Пункт **8** — проверка проходит успешно.
3. Пункт **9** — смоделировать атаку (или открыть `gamechain_data.json` в редакторе и вручную
   изменить, например, `"gold"` или `"email"`).
4. Пункт **8** — программа сообщает, что именно и где было подменено.
